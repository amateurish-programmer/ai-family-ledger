# V1.9.1 报表间距与消费明细解读

versionName 1.9.1 / versionCode 23，基于 V1.9.0（0058ad4）。沿用包名、安装签名、Room V4 和现有家庭数据。

## 修复与行为

- 报表标题与日、周、月、年按钮之间增加 16 dp 留白；三主题统一生效，保留固定区域背景及层级，避免列表内容盖住按钮。
- AI 解读改为「收支概况、消费明细观察、收支建议」，结合消费场景提出可执行的餐饮、固定开支、收入来源和应急储备建议。
- 确认后发送本期及对照期间程序统计，以及本期最多四十笔收支的日期、原始金额、分类、成员、商家和备注节选。账户、记账操作者、导入来源、记录 ID 字段不发送（备注原文可能含记录者自行填写的相关信息）。确认弹窗明确披露发送范围，取消不调用模型。
- 本期四十笔以内发送全部明细；超过时先选十五笔大额支出、五笔大额收入，再用最近记录补满四十笔，按记录 ID 去重。排名与合计使用全部有效人民币收支，不用节选重新计算。
- 支出一级分类前十项、细类前十二项，商家、成员和收入来源各前八项，附精确金额与笔数；一级分类占比由程序以十进制算术计算并四舍五入到两位。各维度互相重叠，不相加。金额合计仍为整数分。
- 模型只写定性解释并选择事实 ID，服务端逐段附上原始标签和值。允许列表编号，不允许模型新写金额、比例或笔数。每段最多六条证据；未知、重复引用或格式错误只修复一次。仍失败则明确显示仅为程序统计，不伪装为 AI 建议。
- 范围始终包含期间完整性、明细覆盖、同步状态及数据限制；未结束期间不与完整期间直接认定增减，结余不是余额或净资产。备注等用户文本一律作为数据，不作为模型指令。
- 请求协议新增 `reportV2`，旧版报告接口保留；修复提示按新旧协议分别生成，避免向旧报告输出要求不支持的 `factIds` 字段。先部署兼容服务，再发布新 APK。

## 排查证据

2026-10-17 读取不含正文的生产诊断事件，报告请求先出现 `ai_output_repair / financial`，随后为 `ai_output_fallback / financial`，同期错误与 502 查询为空。证明此次提示来自财务引用校验后的回退；日志不保存模型正文，无法确定用户该次回复具体是哪一个数值触发。

旧版客户端只提交汇总，不包含消费明细；旧版校验会拒绝任何未提供的新数值、百分比等。新版把解释与数值展示分开，以明确的证据引用避免复制或重新计算金额造成整段回退。
