# 月报 / 年报 AI 解读 502 排查（2026-09-06）

用户反馈：九月仅一笔记录时成功，其他月份或年度报告提示服务端异常。

## 证据与根因边界

控制台 `ledger-ai` Overview 显示近期六次调用、三次 502、4xx 为零，其中失败耗时约 2680 ms，最长约 5689 ms。没有迹象表明这些调用触发了 32 KiB 参数上限、限流或二十五秒模型请求超时。旧函数没有记录模型正文或校验原因，因此无法逐条确认历史失败正文，不能将推测写成已取得的日志事实。

源码存在确定性缺陷：report 输出只要匹配 `[0-9０-９]` 就返回 502。它会把日期、编号和已有统计金额一并拒绝；Android 将该响应映射为通用云端异常。

通过与生产同一 handler、模拟 Auth/家庭/配额/模型返回，用同一份合法汇总复现：普通文字返回 200；正文含 `2026年8月` 或 `1. 建议` 返回 502。此次没有读取实际账目、用户密码或模型密钥，也未发送真实模型请求。

## 修复

- 按原始汇总核对数值引用，允许已提供的年/月、行首编号及准确金额，支持全角数字、千位逗号、负结余。金额比较使用 BigInt 整数分，无浮点。
- 禁止未提供的新数值、百分比及万元/亿元等换算，不让模型重新算账。正文语义仍需人工判断；数值存在性校验不等于全文财务结论验收。
- 模型输出新数值、无效 JSON 或截断时，返回明确标注“AI 文字解读未通过数值或格式校验”的基础摘要，直接引用客户端汇总，不把回退内容冒充 AI 解读。
- Auth/家庭校验、限流、请求大小和网络错误仍正常报错，不用摘要掩盖这些失败。
- 新增仅包含固定事件与固定错误原因的诊断日志，不记录账目、日期、用户身份、金额或模型正文。
- 兼容现有 `{result: string}` 协议，仅更新服务器，V0.7 APK 无需重装。

## 验证与交付

`node scripts/check-report-function.mjs`：十八项模拟回归检查通过，覆盖月份/年度、日期/编号/准确金额、错误数值、格式错误与截断回退。原有六项 chat 协议检查通过。`ledger-ai` 已通过 Supabase CLI `functions deploy --use-api` 部署成功。

用户真实月报/年报的重试结果待反馈；不宣称已在手机与真实 DeepSeek 回复上完成验收。若仍失败，读取新 `ai_request_failed` 或 `ai_report_fallback` 事件即可进一步区分原因。
