# V1.7.0 同步冲突与记账发送修复

本版 versionName 1.7.0、versionCode 20，沿用原包名、Room V4 数据库和开发签名，可覆盖升级 V1.6.1。

## 同步冲突

同步冲突表示同一账目 UUID 的本机内容与云端内容不同，且客户端无法根据上次成功同步的 revision/hash 证明只有一侧修改。真正的一边删除、一边后续编辑仍保留双方并要求用户选择。

此前本机和云端已经分别软删除同一笔账目时，只要两个墓碑的删除时间或保留内容不同，也会产生冲突。两边对有效账本的结论其实一致。本版按删除时间、更新时间和规范哈希选择确定的较新墓碑：云端较新则下载，客户端较新则使用当前云端 revision 做 CAS 上传；并发再次变化仍由 CAS 阻止覆盖。

## 记账输入与 AI 失败

聊天正文限制为 1 至 2000 字；最多生成二十笔待确认记录，金额为 0.01 至 999999999.99 元。发送前必须登录并加入家庭；有待确认记录、正在发送或其他独占操作时不能继续发送。同步过程中输入框保持可编辑，但发送按钮暂时禁用。服务端请求总大小限制 64 KiB，并有每用户/全局分钟与每日额度。

“今天意外收入1034元”不违反任何输入或金额限制。原错误是 HTTP 502 路径：模型上游不可用，或模型返回内容连续两次不满足严格 JSON/提案协议；旧客户端把函数 502 统一显示为“云端服务异常”，无法区分具体类别。

本版采用两层安全回退：

- Edge Function 在模型两次协议修正仍失败时，只对无否定、无将来或不确定语义，且严格符合“今天…收入…金额元”的单笔句子提取原文金额，返回完整待确认提案。
- 新客户端在云端请求失败时，使用既有严格本机解析器尝试简单收支；成功只生成待确认记录，不自动保存，复杂或含糊句仍保留原输入并显示错误。
- 客户端只翻译服务端白名单内的 AI 格式、截断、配置和上游错误，不回显未知服务端正文。

“今天意外收入1034元”会整理为当日收入 1034.00 元、分类“其他收入”，成员与记账人使用本机角色，仍需用户核对账户等字段并确认保存。

## 验证计划

JVM 回归覆盖双端删除时远端较新下载、本机较新 CAS 上传、意外收入本机回退、AI 502 安全文案。Edge Function 合成回归覆盖启用礼金字段时模型连续两次输出无效后，对该原句生成完整收入提案，并继续验证上游 HTTP 失败不被误作格式修正。

云端流水线执行 JVM、lint、APK、后端协议、隔离 PostgreSQL 权限和 Android 35 模拟器检查。Edge Function 源码必须部署到 Supabase 后，旧客户端才能使用服务端回退；APK 发布后新客户端可使用本机回退。真实冲突记录内容与真实模型响应不写入日志或测试夹具。

交付包名为 `AI家庭账本-v1.7.0.apk`，不生成 SHA-256 边车文件。流程完成前不声明已发布。
