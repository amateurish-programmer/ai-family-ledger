# V0.8 家庭同步性能修复

用户反馈一次同步约两分钟。源码确认 V0.7 每次下载全部 payload、每页只有十条，上传逐笔调用 RPC；下载逐笔开启 Room 事务，所有匹配项逐笔同步提交 Preferences。大量串行往返会把网络延迟放大，这是明确的软件性能问题。尚无该手机的请求时序、网络丢包或耗时分解，不能据此把两分钟完全归因于网络或承诺固定秒数。

## 新同步流程

1. 仍先验证登录和家庭成员关系，校验本机快照，并读取完整同步索引。
2. 调用 `get_ledger_manifest(p_family,p_after)`，UUID 游标每页最多 500 条，只返回 `id/revision/payload_bytes`。完整清单用于检测所有已索引记录是否从云端消失、版本是否回退；发现问题后在任何本次账目上传前停止，不自动重建。软删除记录同样包含在清单中。
3. 已同步且 revision 未变化的记录无需再下载 payload。本机 hash 未变化则无需账目或索引写盘；本机修改时进入 CAS 上传。未知 ID、本机缺失或远端版本变化时才按 ID 批量下载，每批最多 50 条，并按 payload 字节数的六倍加结构开销控制最坏 JSON 转义大小。详情响应缺失或重复、版本回退会失败关闭。
4. 下载按批调用已有 `LedgerRepository.applyRemote`，每批一个 Room 事务。只有该事务成功后才批量提交对应 revision/hash。内容相同仅接受索引；不同且双方修改或无共同基线则保留冲突供用户选择。
5. 上传调用 `put_ledger_entries(p_family,p_entries)`，每批最多 50 条且整个请求最多 6 MiB。服务端逐条复用原 `put_ledger_entry`，保持成员检查、payload 校验、认证 actor 和 revision CAS。普通版本冲突不回滚同批其他成功项；无效输入会回滚整个批次。服务端按 UUID 固定顺序执行，减少交叉更新的锁顺序问题。
6. 批量上传响应仅含 ID、ok 和 revision，避免冲突 payload 导致大响应。只对冲突再读最新详情；用户解决冲突前仍再次读取最新版本。成功项索引按批提交，内容相同的重试可恢复丢失的成功响应。网络或冲突再读失败时不假定尚未确认的请求未执行；下次同步用远端内容与本机 hash 恢复。

全量清单及本机备份校验保持 10 MiB / 十万条边界，单条 payload 保持 768 KiB；HTTP 响应仍限 12 MiB。清单与后续详情不是数据库快照，扫描期间新增或继续修改的记录可能到下一次同步才出现。若详情在清单之后增长使响应超限，将报错并在下一次重新取清单，避免接收不受限数据。角色标签继续仅表示业务归属，不影响权限。

## 请求数量对比

以下为一千笔普通大小账目、无冲突、token 有效、无重试时的协议推导。整页扫描需最后一次空页确认，因此一千条清单需要三次请求。包含一次家庭检查，不包含登录。

| 场景 | V0.7 网络请求 | V0.8 网络请求 | V0.8 账目事务 / 索引提交 |
|---|---:|---:|---:|
| 已全部同步、无变化 | 102 | 4 | 0 / 0 |
| 首次上传至空家庭 | 1002 | 22 | 0 / 20 |
| 首次下载一千笔 | 102 | 24 | 20 / 20 |

大来源字段触发字节分批、token 刷新和冲突再读会增加次数。这些是请求结构和测试场景，不是实际手机网速、云数据库吞吐或端到端秒数。

`SyncResult.elapsedMillis` 从获取同步互斥锁后开始，到成功保存 lastSync 为止，包含网络、序列化、本机合并和持久化，不包含等待其他云操作的排队时间。`requestCount` 是期间真正进入 HTTP 请求函数的次数，包括家庭查询、清单、详情、上传、冲突再读及 token 刷新/重试；不会记录账号、token、明细正文或模型密钥。阶段回调显示权限检查、清单、下载及上传状态。失败仍通过原异常提示退出，不把失败当作成功计时结果。

## 接口与部署

新增迁移 `supabase/migrations/202609060002_sync_batches.sql`，无表删除、无已有数据改写，旧 `put_ledger_entry` 和旧 APK 合同保留。新 RPC 固定空 search_path，撤销 PUBLIC/anon 默认执行权，仅 authenticated 可执行，并在函数内再次验证家庭成员身份。必须先应用迁移再分发 V0.8；未部署新 RPC 时客户端明确失败，不隐式回退到较慢接口。

`CloudService.ai` 同步支持 `parse/report/chat/analyze`，输入限制改为 64 KiB，与 V0.8 后端保持一致。LLM 不参与同步合并或金额计算。

## V0.10 前台频率限制

打开 App 或从其他页面返回时，距最近一次成功同步不足 60 秒则跳过自动同步；恰好 60 秒可再次同步。时间沿用持久化 lastSync，重启 App 后仍生效。失败不更新该时间。设备时钟回拨时允许重试，避免永远被未来时间阻塞。手动“同步家庭账本”始终可主动执行。

文件选择器打开期间、文件结果排队时、本机数据加载中或其他操作进行中不启动前台同步。导入、Excel/JSON/报告导出和恢复回调等待既有操作完成，而不是因 busy 丢弃。自动同步开关的默认值不变，本次不新增后台轮询。

V0.10 最终 CI 34042465823：3 项自动同步一分钟边界、重启后持久化时间判断及时钟回拨测试通过；原有同步合并器测试仍通过。真实网络同步频率与手机生命周期未进行生产验收。
