# V1.10.1 移动 5G 连接修复

版本号 1.10.1，版本代码 33，最低 Android API 26。安装包名为 `AI家庭账本-v1.10.1.apk`，可使用原包名与签名覆盖安装 V1.10.0。

## 旧版真机复现

2026 年 11 月 18 日，同一台 vivo V2430A 在中国移动 5G 上运行 V1.10.0。用户反馈联通卡和电信 Wi-Fi 可用。旧版把两张卡都归入纯蜂窝网络，固定选择原 Supabase 入口。

| 移动 5G 实测 | 原 Supabase | Pages 网关 |
| --- | --- | --- |
| 应用内两轮公开更新清单 | 两次建连重置 | 两次 HTTP 200 |
| 应用内两轮 AI 空请求 | 两次建连重置 | 两次预期的未登录 HTTP 401 |
| 独立新连接，两轮 | 两个 IPv4 地址 TCP 均连通，四次 TLS 握手均重置 | 两个 IPv4 和两个 IPv6 地址共八次 TLS 握手成功 |

旧版最近请求中，获取当前家庭在蜂窝网络上发送时发生重置，没有收到 HTTP 状态码。公开探测确认故障可在账号鉴权前复现。重置发生在到原入口的 TLS 握手阶段，发出重置的具体设备尚无法确定。

## 客户端处理

在纯蜂窝网络上，应用先对固定公开更新地址建立匿名 HTTPS 连接。可用的直连线路优先，直连失败时检查现有 Pages 网关。选路结果只在进程内按当前 Android 网络缓存五分钟。切换数据卡会重新选路。Wi-Fi 和 VPN 使用 Pages。

两条短探测均失败时，本次业务仍可用原直连线路和正常超时尝试一次，下一次请求重新探测。只有匿名探测绑定待测蜂窝网络，实际业务连接遵循手机的系统默认网络。

登录、同步、AI、更新清单和 APK 下载共用选路策略。业务请求发出后即使丢失响应，选路层也只将错误交还调用者。下一次独立请求重新判断线路。诊断文件的 `recentRequests[].route` 表示实际业务入口，当前蜂窝网络尚待探测时显示 `pending`。

## 验证

本地使用 JDK 17、Android SDK 35 构建。Gradle 在 Windows 中文路径运行 JVM 测试时遇到测试类加载失败，使用字节一致的 159 个 Android 工程文件在英文路径重跑。240 项 JVM 测试全部通过，跳过数为零。lint 报告 0 个错误和 18 个警告。应用 APK 与设备测试 APK 编译成功。现有网关的 9 项 Node 行为测试通过。

回归覆盖移动 5G 直连重置、可用蜂窝直连、缓存到期、切卡、切到 Wi-Fi 或 VPN、并发共享探测、两路短探测都超时，以及写入响应丢失时只发送一次。另验证旧版诊断记录的兼容读取。

## vivo 覆盖安装与移动 5G 验收

V1.10.1 与手机上 V1.10.0 的签名证书一致。使用系统安装器完成覆盖，回读版本为 1.10.1 / 33。设备中的 APK 与本地交付包逐字节一致，共 18,258,883 字节。

在原来的移动 5G 网络和已有登录会话中，新版诊断记录显示十条云请求均经 Pages 返回 HTTP 200，其中包含三次读取家庭资料、四次读取同步清单。手动点击「刷新家庭资料」的请求耗时 554 毫秒。「设置 → 应用更新 → 检查更新」成功读到公开清单。联网验收使用现有数据的读取路径，未新建测试账目。联通卡和电信 Wi-Fi 的可用性来自用户对旧版的反馈，这两条线路本次未在新版真机上另测。
