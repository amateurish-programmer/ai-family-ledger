# V0.2 Excel 历史账本设计

用户要求继续下一版本，沿用已批准路线与 IMPORT_FORMAT.md 的 V0.2 契约。本轮属于新增导入子系统，交付版本 0.2.0，继续本机离线与云端 APK 构建。

## 方案

采用 Android/JVM 自带 ZIP + SAX 读取有限范围的 XLSX，并生成标准 XLSX 导出。与引入完整办公套件相比，兼容面限定在随手记标准账本，减少 Android 运行时依赖；CSV 中转会丢工作表结构，因此不采用。支持共享字符串、内联字符串、字符串日期及 Excel 数字日期；公式单元格作为错误行，不能用缓存结果记账。

## 数据

Room V1 → V2 非破坏性迁移，在 entries 增加 importDataJson，保存文件 SHA-256、文件名、工作表、行号、导入时间、原始日期、账户2、项目分类、原始列值。domain 使用 ImportOrigin。批次由文件哈希标识，行 ID 由哈希/表名/行号确定，不依赖文件名。保留软删除行以防旧文件复活。

支出和收入为正整数分；余额变更允许有符号和零金额，仅表示来源原值，暂不推断账户余额。成员/记账人缺失使用明确的“未指定”标签，同时保留原字段。分类/账户缺失的收支行列为错误。完整 JSON 备份升至 V2，仍可读取 V1；V2 必须保存来源信息，编辑时保留来源。

## 用户流程

设置页选择 XLSX → 显示各表数量、收支金额、错误/已导入/疑似重复 → 可筛选并逐行勾选 → 确认所选记录并事务写入。默认选中新记录；已导入不可选；疑似重复默认不选，但用户可明确保留。不同文件同内容以及文件内部相同交易均提示疑似重复，比较时忽略来源、更新时间，日期精确到天以涵盖手工记录。

预览只读，取消不写库。确认前在数据库事务中复核稳定 ID；无效数据不部分写入。批次历史显示来源/数量/导入时间，撤销批次需确认并软删除本批次全部记录（包括后续编辑过的记录），不会影响其他批次和手工记录。撤销后同文件仍显示已处理，避免误复活。

导出当前未删除记录到三个标准工作表；导出只代表表格数据交换，不保留 UUID/删除标记，完整迁移应使用 JSON 备份。文本以显式字符串写入，不能被 Excel 当作公式执行；金额为数值、两位小数。导出保留时间、账户2、项目分类。

## 边界与验证

仅 XLSX/CNY；文件 5 MB，解压总量 16 MB，最多 10,000 数据行、64 列；拒绝 DTD/外部实体/重复 ZIP 路径，限制单元格文本长度。解析和文件操作在 IO 线程。未知工作表在预览说明中列明。

只读核实真实工作簿：426 支出、31 收入、6 余额变更，三表均 CNY，日期为字符串。测试与截图使用合成数据；真实文件不上传。

核心测试覆盖表头换序、中文/多行字符串、日期、金额精度、重复规则、导出回读、恶意/损坏文件和 V1/V2 备份。Android 测试覆盖 V1 数据库升级保留记录、导入幂等、事务回滚、批次撤销、来源编辑保留、预览到入账 UI；最终构建/测试证据记录于 VALIDATION.md。
