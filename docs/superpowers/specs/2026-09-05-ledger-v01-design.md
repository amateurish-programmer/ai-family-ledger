# AI 家庭账本 V0.1 设计

依据：用户引用《规划AI记账App》并要求按记录开始开发。沿用已选 Kotlin + Compose、Room 离线优先、后续 Supabase 云端服务和 GitHub Actions APK 路线。本轮是第一阶段可用本地账本与构建交付，不将全部规划冒充为已上线。

## 本轮交付

- Android 8.0+（minSdk 26），Kotlin、Compose Material 3、ViewModel/StateFlow、Room。
- 首次启动空账本；手工新增、修改、删除收入和支出，保留日期、一级/二级分类、账户、成员、记账人、商家、项目和备注。
- 金额以 CNY 整数分存储，拒绝非正金额、超出两位小数和超出范围；统计整数运算，禁止 LLM 计算钱。
- 首页按月查看流水与收支结余；报表按月/年查看支出分类合计。基础报表无 AI 文案。
- 录入表单错误提示，重复点击保存保护，删除前确认，数据库写入失败保留表单。
- JSON 完整备份导出及恢复预览，同一 UUID 不重复恢复；失败整批回滚；文件仅通过系统文件选择器访问。
- 云端 CI：单元测试、Android lint、Debug APK 上传，手动或 push 触发。
- 测试采用合成数据，真实 Excel 不进入 Git 或 APK。

## 技术边界

界面读取 Room 数据流；Repository 封装写入及备份恢复，ViewModel 负责状态和错误。domain 层负责金额验证、日期校验、报表计算，独立于 Android 可单元测试。数据库持久化使用 UUID 标识和软删除，为后续同步保留更新时间，不启用破坏性迁移。

首版仅一个本地账本，不伪装家庭登录或同步完成。成员是支出归属标签，不是认证用户。正式同步阶段须用 Supabase Auth 用户 ID 作为操作者，不能信任客户端任意填写的记账人。

## 后续阶段

1. V0.2：随手记 Excel 导入/导出，三类工作表、规范化、预览、疑似重复确认和批次追溯。余额变更原始金额语义仍须确认，不能直接当成收入。
2. V0.3：主动语音输入、规则与大模型解析、可编辑确认卡；模型密钥只在 Edge Functions。
3. V0.4：Supabase 登录、家庭邀请、RLS、离线同步队列、冲突处理和跨家庭隔离测试。
4. V0.5：月报/年报趋势、成员维度、AI 解释、报告导出。

## 验收边界

本地静态检查、核心逻辑测试、Android 构建、设备安装、Supabase 云端联调分别记录。无 GitHub 仓库与云端配置时，仅交付可上传项目，不能宣称已部署或已生成 APK。

## 界面

浅色暖白背景，深绿主色，大数字显示本月结余。底部导航：账本、报表、设置。流水使用轻分隔线；新增/编辑使用完整滚动表单。避免在账本默认插入虚假演示流水。
