# V1.8.0 AI 与对话体验升级实施计划

**Goal:** 在 GitHub main v1.7.0 基线上修复误归属与财务回退，增强多组查账、持续上下文、分析思考，并分页展示对话后发布 v1.8.0 / code21。

**Architecture:** 保留 Room V4 与现有家庭同步。新版通过 analysisV2 能力标记使用兼容扩展的 AI 协议，最多四组本机受控查询，再由模型解释程序计算的事实。旧客户端协议保留。历史显示与 AI 记忆分离。

**Tech Stack:** Kotlin / Compose / Room / TypeScript Deno / Supabase / GitHub Actions。

**Spec:** 用户已在当前会话批准前轮审查建议并要求提交发布；本计划固化具体实现边界。

## 全局约束
- 金额整数分与精确十进制；AI 不计算总额、自动保存、直接执行 SQL。
- 保留包名、签名、数据库、所有本地未上传数据；不生成本机 SHA-256 边车。
- 新模型功能不改变权限边界；真实账本、凭据不写日志或测试。
- 在 origin/main 65dce34 上创建隔离分支；旧工作目录只在保存差异快照后统一至发布版本。
- 版本 v1.8.0 / versionCode 21。

## 协议约定
- 新 chat 输入增加 analysisV2:true 与 memory:字符串数组（最多8项，每项500字）；history仍最多8条，每条最多1500字。
- 新服务端对 App 返回 {reply,entries,query:null,queries:[]}，queries最多4项。旧客户端仍返回原三字段。
- 新查询字段：start,end,member,category,keyword,label,type,giftOnly,counterparty；后三筛选分别为 ""/INCOME/EXPENSE、布尔、人名字符串；日期左闭右开。ChatQuery 新字段有默认值以兼容旧调用。
- 新模型 chat 输出额外 factIds:字符串数组，服务端验证并渲染为“原始事实标签：原值”，移除 factIds 后才返回 App。分析输出 {reply,factIds}。说明文本不自行写金额/数量，事实区域显示金额与范围。
- FinanceContext.buildQueries(entries,today,lastSync,queries) 返回与原 finance 相同的 scope/facts/limitations 结构，最多160个事实。提供多组统计、分类/成员/商家和礼金、有限明细、程序计算差额。明确期间完整性与数据范围。
- ConversationMemory.history(messages) 返回8条有界上下文；memory(messages) 返回早期重要用户陈述，最多8项，去重、保留来源且不当成已验证财产。context(reply,queries) 保存最近查询条件到现有 ChatMessage.context，兼容旧文本。
