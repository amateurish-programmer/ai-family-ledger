# V0.11 应用内更新实施计划

用户已批准 GitHub Actions 构建、Supabase 托管、设置手动检查下载并覆盖安装的方案。

1. 固定 app-updates Storage 目录托管版本元数据与不可覆盖的版本 APK；公开只读，服务端发布，账本和模型配置不变。
2. AppUpdate 严格解析版本、包名、SDK、文件路径、大小、SHA256 与说明；检查后由用户选择下载。下载有进度/取消/重试，HTTPS 固定源，失败清理临时文件。
3. 下载完成核对完整文件与安装签名，FileProvider 仅暴露 updates 子目录；请求系统安装来源权限，返回后由用户点击安装，保留系统确认流程。升级不卸载、不清账本。
4. 更新状态使用独立 ViewModel，页面切换或旋转不中断当前协程；不持有旧 Activity launcher。进程被终止可重新检查下载，不承诺后台永久服务。
5. CI 经 JVM、模拟器和后端检查通过后发布版本；使用 GitHub Secrets 中的服务端凭据，不上传失败构建，不把密钥写入 APK 或日志，元数据保存校验值而非本机 SHA 文件。
6. 合成测试覆盖元数据/降级/来源/损坏包、更新 UI 状态和发布幂等/倒退/上传失败。部署后匿名读取版本及完整下载安装包进行校验。记录签名一致性与真机系统安装验收边界。
7. 升级0.11.0/code11，明确文件清单签名提交，构建交付 AI家庭账本-v0.11.0.apk。用户先手动安装该版本一次，后续更新使用新入口。
