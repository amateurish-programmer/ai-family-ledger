# V0.8.0 · 家庭财务对话与温馨界面

## 问题与方案

V0.7 对话确实调用模型，但模型只收到分类/成员名称和用户文字，查询后由 App 输出固定统计；查询结果不再交给模型，后续上下文也只保留筛选条件。因此家庭财务分析和连续追问能力不足。

V0.8 每轮提交程序计算的有限财务摘要，包含所选范围合计、最近十二个月、最近十二个有记录年份、主要分类与成员支出。本机原始账目备注、账户名称和导入来源不进入摘要。历史保留最近八条、每条最多七百五十字，最新统计优先。

一般财务问答一次模型调用即可解释已有数据；需要额外日期/成员/分类/关键词筛选时，模型先给条件，App 精确筛选计算，再进行分析调用。第二次分析失败会明确显示失败原因和程序统计，不伪称 AI 成功。每次调用仍消耗既有服务端限额；专门查询可能使用两次额度。

金额继续采用整数分计算。AI 以事实 ID 引用金额，服务端原样展开引用，不让模型重写所引用金额。未知引用和裸金额/比例触发带标记的程序统计回退。该机制不代表模型的语义判断绝对可靠：AI 仍可能误解问题，需要用户判断。账本结余不等于家庭净资产，未记录月份不能推断实际零消费。财务建议限于有依据的预算、消费、储蓄与债务梳理；信息缺失时追问，不承诺收益或给出具体证券买卖指令。

记账提案继续经确认后保存；权限仍依赖 Supabase Auth，角色仅用于归属标记。

同步实现与请求次数见 [同步性能说明](SYNC_PERFORMANCE.md)。视觉设计见 [界面说明](UI_V0.8.md)。
