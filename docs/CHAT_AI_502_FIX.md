# 工资入账 HTTP 502 修复

## 现象与定位

生产环境中“午餐13块”可以正常生成支出提案，而“今天老婆工资入账5450”返回 HTTP 502。Edge Function 日志显示请求已经通过认证、家庭和额度检查，模型也在约三秒内返回；失败原因均为“AI 输出不符合提案或报告格式”。因此故障位于模型响应的 JSON/提案协议校验，不是客户端网络、Supabase 认证或 DeepSeek 超时。

## 修复

`ledger-ai` 明确把“工资到账”“工资入账”识别为已发生的 `INCOME`，并把明确的收入归属人写入 `member`。首次模型响应到达但 JSON 或严格提案协议校验失败时，服务端使用原始输入追加一次精确协议说明，请模型重新生成；第二次响应仍经过相同的完整校验，金额、日期、字段集合、确认流程和人情字段约束均未放宽。

格式修正最多执行一次。模型服务的 HTTP 错误、超时、认证或限流错误不会进入格式修正重试。日志只记录 `ai_output_repair`、`ai_output_repaired` 或 `ai_output_repair_failed` 及错误类别，不记录对话、金额、账户或模型原文。

## 验证范围

合成服务端回归覆盖：工资收入首次返回多余字段、第二次返回合法提案后成功；模型 HTTP 503 只调用一次且仍返回 502；既有财务问答、查询、提案确认、报告回退和人情协议继续通过。合成测试不联系真实模型，也不使用家庭账本。

这是服务端兼容修复，不改变 Android 包、Room 数据库或同步协议。部署新的 `ledger-ai` 后，已安装的 v1.3.0 会直接使用修复后的服务，无需重新安装 APK。真实账号和生产 DeepSeek 响应仍需用原问题复测。
